How it was made

The engine, the games and this site, made by talking with Claude Code and measured on the real board.

In numbers

  • 16.489lines of C in the engine
  • 33example games
  • 117tests on every change
  • 237commits in the repository

One person and Claude. The engine, examples, tools and this site were written in conversation with Claude Code: every idea was tried in the simulator, measured on the board and corrected based on what the board showed.

The art, generated and made to fit. The looks that call for it (Neo Geo, CPS2, 32-bit) use AI-generated images. The engine's tools cut them out, scale them to the right height, split them into frames and reduce them to the console's palette. The low-res looks are drawn with code.

Measured before calling it done. Every example has a script that plays it automatically. On the computer, it checks each frame's checksum against the stored one; on the board, it logs the fps every second. Optimisations don't change a single pixel.

Truly free. The code is MIT; the examples' art, sound and videos are CC0. Take it, change it, build your own console.

Measured on the console, not promised

Every figure in this section comes from the board: firmware that plays each game from a script and logs a performance line every second, or a benchmark that runs each scene five times. No emulator. At 60 fps, each frame has a 16.6 ms budget.

  • 71%of one core in the heaviest scene: affine, four layers and 128 sprites
  • 8,1msto send a whole frame to the panel; the wire alone takes 7.7
  • 3%of one core for sound during play
  • 117self-playing tests that check every frame, run on every change

Source: docs/measurements.md (opens in a new tab), with the method and every measurement since day one. Measure it on your own board: idf.py -DBP_BENCH=ON build flash monitor
