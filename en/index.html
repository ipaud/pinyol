Measured on the console, not promised

Every figure in this section comes from the board: firmware that plays each game from a script and logs a performance line every second, or a benchmark that runs each scene five times. No emulator. At 60 fps, each frame has a 16.6 ms budget.

  • 71%of one core in the heaviest scene: affine, four layers and 128 sprites
  • 8,1msto send a whole frame to the panel; the wire alone takes 7.7
  • 3%of one core for sound during play
  • 111self-playing tests that check every frame, run on every change

Source: docs/measurements.md (opens in a new tab), with the method and every measurement since day one. Measure it on your own board: idf.py -DBP_BENCH=ON build flash monitor

Make your own game

pinyol is designed to be used with a coding agent such as Codex or Claude Code. The agent reads the repository's instructions, installs whatever is missing, follows the recipe for the look you ask for and tests the game before handing it over.

  1. Get the engine

    On a Mac with Homebrew, or on Linux.

    git clone https://github.com/ipaud/pinyol.git
cd pinyol

  2. Ask your agent

    Open the folder in your agent and tell it what you want, in your own language.

    Make me a platformer with a Game Boy look: a mouse looking for cheese in a library.

  3. Play it

    On the computer, or send it to the console over USB.

    ./build/pinyol_sim --game games/raton
No coding? The web editor does the same with drawings and blocks, in the browser.

The editor

Draw your characters pixel by pixel, paint the maps, set the rules with blocks and play straight away. Start from scratch or from a template such as Abella or LÍNEA 0.

  • Console look Game Boy, Game Boy Advance, PICO-8, ZX Spectrum or 16-bit, with its colours and font
  • Drawings that move pixel by pixel, with animations for standing, walking or getting hit
  • Rules with blocks lives, a countdown, dialogue, saved high scores
  • Sound effects from recipes, music composed on a grid, or a .mod
  • To the console over the USB cable, or as a .zip for the microSD card
  • In three languages castellano, català and English

The console

An off-the-shelf development board with a screen. The engine gets the most out of it: it draws straight into strips, splits the work between the two cores and keeps whatever doesn't fit on the microSD card.

Board
Freenove FNK0104N
Chip
ESP32-S3R8, two cores at 240 MHz
Memory
512 KB of internal RAM, 8 MB of PSRAM, 16 MB of flash
Screen
3.5″, 480×320, ST77922 over QSPI, touch
Sound
ES8311 with speaker
The rest
microSD, battery, USB

Install the firmware from the browser

  1. Connect the board to your computer over USB.
  2. Press the button and choose the board's port.
  3. Wait a few minutes: it boots up with 15 games in memory.
This browser can't talk to the board over USB: open this page in Chrome or Edge on a computer. Installing requires HTTPS.

In RetroArch and RetroPie

No console? The engine is also a libretro core: pinyol games play in RetroArch and in everything built on it, such as RetroPie or Lakka on a Raspberry Pi, Batocera, Recalbox, the handhelds that run it, or a computer. It is the same engine, so the game is the same.

  1. Install it on RetroPie

    On the Raspberry Pi, this command builds the core (it takes a few minutes) and adds Pinyol to EmulationStation.

    cd ~/RetroPie-Setup
curl -fsSL --create-dirs \
  -o ext/pinyol/scriptmodules/libretrocores/lr-pinyol.sh \
  https://raw.githubusercontent.com/ipaud/pinyol/main/platform/libretro/lr-pinyol.sh
sudo ./retropie_packages.sh lr-pinyol

  2. Copy the games

    Any game's .zip, like the ones you can download here, goes in its folder.

    ~/RetroPie/roms/pinyol/

  3. Play

    Restart EmulationStation and Pinyol shows up with its games. On the gamepad, X or Y act as C, and SELECT as MENU.

Another RetroArch? On a computer, Batocera or Lakka, the core is added by hand: how to build it and where it goes (opens in a new tab). Tested in RetroArch and on an emulated RetroPie system, not yet on a real Raspberry Pi: if you try it, tell us how it goes (opens in a new tab).

How it was made

  • 15.373lines of C in the engine
  • 33example games
  • 111tests on every change
  • 168commits in the repository

One person and Claude. The engine, examples, tools and this site were written in conversation with Claude Code: every idea was tried in the simulator, measured on the board and corrected based on what the board showed.

The art, generated and made to fit. The looks that call for it (Neo Geo, CPS2, 32-bit) use AI-generated images. The engine's tools cut them out, scale them to the right height, split them into frames and reduce them to the console's palette. The low-res looks are drawn with code.

Measured before calling it done. Every example has a script that plays it automatically. On the computer, it checks each frame's checksum against the stored one; on the board, it logs the fps every second. Optimisations don't change a single pixel.

Truly free. The code is MIT; the examples' art, sound and videos are CC0. Take it, change it, build your own console.
