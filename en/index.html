Measured on the console, not promised

Every figure in this section comes from the board: a firmware that plays itself from a script and writes a performance line every second, or a bench that repeats each scene five times. No emulator. A frame at 60 fps has 16.6 ms.

  • 71%of one core in the heaviest scene: affine, four layers and 128 sprites
  • 8,1msto send a whole frame to the panel; the wire alone is 7.7
  • 3%of one core for the sound while playing
  • 109tests that play by themselves and compare every frame, on every change

Source: docs/measurements.md (opens in a new tab), with the method and every measure since day one. Measure it on your board: idf.py -DBP_BENCH=ON build flash monitor

Make yourself a game

pinyol is meant to be used with a coding agent, such as Codex or Claude Code. The agent reads the repository's instructions, installs what is missing, follows the recipe of the look you ask for and tests the game before handing it to you.

  1. Get the engine

    On a Mac with Homebrew, or on Linux.

    git clone https://github.com/ipaud/pinyol.git
cd pinyol

  2. Ask your agent

    Open the folder with your agent and tell it what you want, in your own language.

    Make me a Game Boy-look platformer: a mouse looking for cheese in a library.

  3. Play it

    On your screen, or send it to the console over USB.

    ./build/pinyol_sim --game games/raton
No coding? The web editor (opens in a new tab) draws the sprites pixel by pixel, paints the maps and tests the game in the browser itself.

The console

A ready-made development board with a screen. The engine squeezes it: it draws straight into strips, shares the work between the two cores and keeps on the card what doesn't fit.

Board
Freenove FNK0104N
Chip
ESP32-S3R8, two cores at 240 MHz
Memory
512 KB of internal RAM, 8 MB of PSRAM, 16 MB of flash
Screen
3.5″, 480×320, ST77922 over QSPI, touch
Sound
ES8311 with speaker
The rest
microSD, battery, USB

Install it from the browser

  1. Plug the board into the computer over USB.
  2. Press the button and choose the board's port.
  3. Wait a few minutes: it starts with 15 games in its memory.
This browser can't talk to the board over USB: open it in Chrome or Edge, on a computer. Installing needs the page on https.

How it was made

  • 15.250lines of C in the engine
  • 33example games
  • 109tests on every change
  • 143commits in the repository

One person and Claude. The engine, the examples, the tools and this site were written talking with Claude Code: every idea was tried in the simulator, measured on the board and corrected with what the board said.

The art, generated and fitted. The looks that need it (Neo Geo, CPS2, 32-bit) use AI-generated images. The engine's tools cut them out, scale them to the right height, split the frames and reduce them to the console's palette. The small looks are drawn with code.

Measured before calling it done. Every example has a script that plays it by itself. On the computer it compares each frame's checksum with the stored one; on the board it writes the fps of every second. Optimisations don't change a single pixel.

Truly free. The code is MIT; the examples' art, sound and videos, CC0. Take it, change it, make your console.

The whole process is in the repository: how the art is made (opens in a new tab), the Lua API (opens in a new tab), the instructions for agents (opens in a new tab).
